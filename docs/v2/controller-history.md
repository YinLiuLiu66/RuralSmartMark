# 总控历史会话抽屉 + 会话重命名（方案草案，未拍板）

状态：草案。讨论中，尚未落 decisions；拍板后本文件收敛进 `controller.md` 契约 + decisions #N，或直接删除。

## 背景与目标

- 现状：会话历史全量落库（`ControllerMessage`），但浏览层缺失——面板只显示当前 (产品， 批次) 绑定的会话，没有列表入口，失联会话（绑定批次已删）再也无法打开。
- 目标 1：总控面板加「历史」入口，列出全部会话，可回看、可接着聊。
- 目标 2：会话可重命名，入口只在抽屉里（用户明确要求）。

## 后端设计

### 新接口

1. `GET /api/controller/sessions?limit=50`
   - 按会话 `updated_at` 倒序（最近聊过的在前）。
   - 每条返回：`id`、`title`（用户命名，可空）、`product_id/product_name`、`batch_id/batch_code/batch_state`、`message_count`、`preview`（首条用户消息截 40 字，无消息为空）、`created_at/updated_at`。
   - 展示名规则：`title` 优先；为空时前端派生——绑定了批次用「产品名 · 批次码」，空白会话用「新产品调研」。
2. `PATCH /api/controller/sessions/{id}`，body `{ "title": string }`
   - 去空格、最长 120 字；空串表示清除命名、回到派生名。
   - 返回复用 `ControllerSessionOut`。

### 数据迁移

- `ControllerSession` 加一列 `title: String(120), nullable=True`，Alembic 迁移一版。
- 命名跟随会话终身：空白会话被命名后，确认建档改绑产品/批次时 title 保留（调研时的名字带进正式会话）。
- 外键保证无孤儿：批次删除 → `batch_id` 置空；产品删除 → `product_id` 置空。列表里显示「未绑定批次」「（产品已删除）」，不会出现指向不存在对象的行。

## 前端设计

### 抽屉

- 入口：总控面板头部「历史」按钮（带消息数为 0 的会话也列出，标「（空会话）」）。
- 列表行：标题（title 或派生名）+ 绑定信息一行小字 + 相对时间；hover 出铅笔图标 → 行内输入框改名（回车保存 / Esc 取消）。
- 点行打开该会话，分两种：
  - **可接上**：会话绑定的产品/批次仍存在 → 沙盘选中同步切过去（复用 #88 的批次同步通道），面板自然接上那条线，可继续聊。
  - **失联**（未绑定批次或产品已删）→ 只读回看：消息完整展示，输入框禁用并提示「该会话未绑定批次」。

### 会话选中状态（实现关键）

- 面板现有 `useEffect` 按 `(productSlug, batchId)` props 拉会话；打开历史会话后若不处理，任何一次 props 变化都会把面板拉回当前选中组合。
- 增加 `sessionOverrideId` 状态：点历史会话时置为该 id 并按 id 拉取，props 驱动的 effect 暂不生效；用户在沙盘里切产品/批次时清除 override，回到自然绑定。失联会话打开即处于 override 只读态。

## 不做与待定

- 不做：会话删除、会话归档/搜索、跨会话合并；消息不可编辑。
- 待拍板问题：
  1. 失联会话默认只读，还是允许在原会话继续聊（后端 `_run_turn` 按会话自身绑定取上下文，技术上可行）？
  2. 要不要顺手做「删除空会话」（消息数为 0 的可清掉，避免列表膨胀）？
  3. 重命名的标题是否同时显示在消息区顶部作为当前会话名？
