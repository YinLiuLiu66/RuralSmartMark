# 项目信息卡 · 智农云链

## 1. 项目身份

- 正式名：《“智农云链”——基于多智能体协同的县域农产品品牌数字化重构系统》
- 对外简称：**智农云链**
- 代码/仓库标识：`RuralSmartMark`（只用于技术文档，不进 PPT 标题）
- 首个案例：**昭通丑苹果**，云南省昭通市昭阳区
- 演示合作社子品牌：**乌蒙丑果**；演示 IP：**山风守园人**
- 产品规格：5kg / 12 枚礼盒，果径 80–85mm
- 一句话：让一个县域农产品批次，从地头价走到品牌价——四个 AI Agent 在 3D 沙盘上完成故事、包装、内容、定价与溯源。
- 当前状态：Phase 0–6 已完成（截至 2026-10-22 的记录），处于交付与补证阶段；已完成项与缺口见第 7、8 节。
- 线上地址：<https://rsm.yinliuliu.com>；固定溯源页 <https://rsm.yinliuliu.com/trace/ZTDEMO26>。主站、总控、H5 都公开访问，不需要账号；如果打开时弹账号框，说明公开访问还没生效，找负责人。

**注意**：昭通苹果是真实区域公用品牌；合作社、子品牌、IP、果农人物均为演示合成，不冒充区域品牌，不暗示官方授权。

## 2. 为什么做

县域不缺好产品，也不缺区域品牌；缺的是自己把产品做成品牌的能力：

- 做一套包装、故事、内容、定价，通常要分别找设计、文案、运营、定价，周期长、费用高（项目估算），小批量做不起。
- 结果是好果子只能按斤卖，溢价留在渠道，不在产地。
- 项目把这条链路做成**可复制的流水线**：AI 出初稿，人做判断与润色（“80%/20%”是产品定位，不是实测比例），一个批次从田间走到消费者。

**为什么选昭通丑苹果**：

1. 故事钩子强：“丑”是天然反差；高海拔、日照长、昼夜温差大是可引用事实。
2. 视觉辨识度高：红果、绿园、牛皮纸礼盒，低多边形场景容易出效果。
3. 溢价链条清楚：散装地头价与品牌礼盒价对比直观。
4. 公开资料足够：国家地理标志、昭阳区核心产区、品质指标、2024 年产业规模都有可引用来源。
5. 叙事空间大：乌蒙山、近百年引种培育；未核到与产区直接关联的文化素材不进入故事。

## 3. 产品是什么

**两个端**：

- 桌面 **3D 沙盘**：县域品牌流水线工作台，四站点、批次、包装、广告牌、二维码、卡车。
- 手机 **溯源 H5**：390px，消费者扫码看故事/IP 插画/包装/价格/时间线/IP 对话。

**一个批次的六步**：

| 步骤 | 发生什么 | 产出 |
|---|---|---|
| 1 原料入库 | 果园/合作社登记批次、产地、采摘日期、糖度、数量 | 批次档案 |
| 2 故事馆 | Agent 1 读知识库与口述，定 IP、写品牌故事 | IP 定位、长/短故事、标签、引用证据 |
| 3 包装工坊 | Agent 2 把故事变成包装概念与文案 | 包装文案、色板、结构/成本、3D 盒贴图 |
| 4 内容工坊 | Agent 3 生成渠道内容 | 小红书/抖音/朋友圈、客服 Q&A、KOL Brief |
| 5 云仓/门店 | Agent 4 算价格梯与溯源 | 三档价格、毛利、溢价、二维码、溯源时间线 |
| 6 消费者扫码 | H5 打开，IP 讲这批果子的旅程 | 扫码事件、IP 对话 |

**三个机制**：

- **人工审核**：每站完成即暂停，运营者可改文案、写一句“更乡土一点”重跑；通过后才进下一站。
- **早期站回退**：回到故事或包装重做时，下游产出与 artifact 作废重跑，历史 run 保留。
- **总控**：一个对话入口，能调研建档、跑四站、审核/驳回/回退、给当前产品开批次、删批次；写操作先出确认卡。

## 4. 创新点与差异化

做 PPT 的“创新点”页可直接从这里挑 4–5 条，每条都对应已实现的功能，不是概念：

1. **端到端流水线，不是单点工具**：故事、包装、内容、定价四站共享同一批次上下文，上游通过才进下游；同类工具通常只解决包装设计或文案生成。
2. **人的审核 + 早期站回退**：AI 出初稿，人改/驳回/回退；回退会作废下游产出并重跑，历史 run 保留。通用聊天机器人没有这个状态机。
3. **事实约束可机器校验**：知识库是唯一事实源，引用必须逐字出现；FactGuard 硬拦截未认证、医疗功效、保证增收类表述，未引用数字给 warning。这是事实可信度的关键，不是靠提示词自觉。
4. **确定性定价，LLM 不碰数字**：成本、三档价格、毛利、溢价由服务端计算器算，LLM 只写解释；每个数字可手算复现。
5. **交付物闭环，同源一致**：同一张包装 PNG 用于 3D 盒贴图与溯源页；二维码指向同一批次的 H5；消费者扫码看到的就是审核通过的内容。
6. **档案化可复制**：换产品只换 `ProductProfile`、知识库、包装模板、基准价四样，Agent/编排器/审核流/H5/沙盘不改；麻江蓝莓、平泉香菇两批已真实跑到 `traced`。

**和常见做法的区别：

| 常见做法 | 本项目 |
|---|---|
| 通用大模型/聊天机器人 | 有状态机、审核、产出物、事实校验、回退 |
| 设计工具（Canva 等） | 不只包装视觉，还做故事、内容、定价、溯源 |
| 单点 SaaS | 带县域产品档案与区域事实约束，可复制到不同产品 |
| 人工代运营 | 把一次性的策划变成可重复的流水线，人只做判断 |

## 5. 可复制性与价值逻辑

**可复制性**（PPT 的“能否推广”页）：

- 换产品 = 新档案 + 知识库 + 包装模板 + 基准价 + 场景预设；不改 Agent、编排器、定价、包装、H5 代码。
- 已用两个真实产品验证：麻江蓝莓（贵州）、平泉香菇（河北），从总控调研建档跑到 `traced`，输出无昭通/苹果残留。
- 首个案例只做单案例深做，不追求产品数量；可复制性靠档案结构，不靠复制代码。

**价值逻辑**（只能写到这个程度，不要编数字）：

- 对合作社：把一次性的设计/策划/定价能力，变成按批次可重复的流水线。
- 对产地：让溢价环节尽量留在本地，而不是全部留在渠道（这是逻辑，不是增收承诺）。
- 对县域：档案化后可复制到其他农产品，边际成本主要是调研与知识库建设。
- 对消费者：扫码看到故事、包装、价格公式与时间线，信息更透明。

**不能写的**：带动多少农户、增收多少元、覆盖多少县域——这些没有实测或书面依据，写了就是编。

## 6. 技术事实（如果要做技术页可以用这些）

**架构**：React 19 + React Three Fiber 9 + Zustand + Tailwind 4 的前端；FastAPI + SQLAlchemy 2.0 async + SQLite 的后端；SSE 实时事件；LLM / 图像 / 搜索三类 Provider 可插拔（指可以更换模型）。

| 层 | 选型 |
|---|---|
| 前端 | React 19、TypeScript、Vite、R3F 9 + Drei、Zustand、Tailwind CSS v4、原生 `<dialog>` |
| 3D | 代码拼低多边形几何体 + 平面材质 + Texture；广告牌/二维码用 Html 覆盖层；不引 GLB/写实资产 |
| 后端 | FastAPI、Pydantic v2、SQLAlchemy 2.0 async、aiosqlite、Alembic |
| 实时 | `sse-starlette`；单 worker + 内存事件总线；断线指数退避重连后重拉快照 |
| LLM | OpenAI 兼容端点；默认 SiliconFlow `deepseek-ai/DeepSeek-V4.1-Flash`；结构化输出 + 校验失败重试 + 无 key/失败降级 mock |
| 图像 | SiliconFlow `Tongyi-MAI/Z-Image-Turbo`；按 prompt hash 缓存；失败不影响审核 |
| 搜索 | Firecrawl 异步搜索/抓页；无 key 时提示贴来源，不静默编资料 |
| 包装 | Pillow 服务端渲染 PNG；内置 Noto Serif/Sans SC（OFL）；二维码 `qrcode[pil]` |
| 数据 | SQLite 11 张表；单用户、WAL、单 worker |
| 部署 | nginx 托管静态 + systemd 单 worker uvicorn；不做 Docker |

**四个可替换组件**：`ProductProfile` 产品档案、知识库文档集、包装模板、基准价集合。换产品 = 换这四样，Agent、编排器、审核流、溯源 H5、沙盘骨架都不改。

**数据模型（11 张表）**：产品档案、批次、Agent 运行记录、产出物、知识库、价格基准、KOL、扫码事件、溯源对话、总控会话、总控消息。

**关键机制**：

- **结构化输出**：每个 Agent 输出 Pydantic 校验过的 JSON；失败带错误信息重试一次；仍失败标记 failed，保留已有产出。
- **知识库与 FactGuard**：`data/knowledge/zhaotong/*.md` 是唯一事实源；引用必须逐字出现在正文；硬拦截未认证（有机/绿色食品/富硒）、医疗功效、保证增收/卖完；未引用数字给 warning。
- **确定性定价**：成本、三档价格、毛利、溢价由服务端计算器算；LLM 只写解释；输出带公式与 `is_demo=true`。
- **包装合成**：服务端渲染 1600×1000 印刷示意 PNG，同一张图用于 3D 盒贴图与溯源页；三个色板变体只改颜色。
- **多产品**：产品下拉切换，批次按产品过滤；新产品由总控调研/确认后写入，不 seed、不做第二套 3D。
