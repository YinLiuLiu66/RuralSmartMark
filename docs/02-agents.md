> 状态：🟢 Agent 1/3 已落地（M4）— Prompt 见 `backend/src/ruralsmartmark/agents/prompts.py`，素材见 `agents/materials/`；Agent 2/4/5 仍为设计稿

## 0. 什么是 Agent（本项目语境）

一段**调用大模型（OpenAI 兼容 API）完成特定任务**的后端程序。
不是机器人软件，而是五个"AI 员工"，各管流水线上的一段：

```
Agent1 写故事 → Agent2 照着画图 → Agent3 拿去吆喝
                                        │
Agent5 管仓库调度 ←—— 礼盒在沙盘里流转 ——→ Agent4 算账 + 顾客扫码看全程
```

**沙盘与 Agent 是一体的**：Agent 生产的礼盒"入库"后变成 3D 沙盘里真实流动的托盘；
沙盘记录的每段运输变成消费者扫码看到的溯源故事。

## 1. Agent 1 · 乡土故事挖掘机（文化溯源与 IP 定位）

| 项 | 内容 |
| --- | --- |
| 职责 | 为农产品提炼文化基因，产出品牌故事与 IP 定位 |
| 输入 | 产地（县名/品类）、农户口述资料（文字转写）、地方传说等素材（见 §1.1） |
| 处理 | 素材归纳 → 文化元素提炼（历史/非遗/地理标志）→ 故事生成 |
| 输出 | 品牌故事文案 + IP 定位语（供 Agent 2 与详情页使用） |
| 依赖 | LLM（文本）；后续可加知识库检索（pgvector） |
| 优先级 | ⭐ MVP 必做（纯文本，最易出效果） |

### 1.1 输入素材与事实注入（decisions #27 / #28 / #29）

- **固定素材包**：`backend/src/ruralsmartmark/agents/materials/majiang.json`——县名、品类、地理标志与产业事实（附出处）、农户口述、苗族传说。
- **运行时事实**：合作社名、站点、冷链温度区间、运输时长从 DB 查（`agents/context.py`），只拼 3–5 个数字进 Prompt，不塞整份快照。
- **虚构边界**：麻江县与蓝莓产业事实真实可查；合作社名、站点、车牌为演示虚构，素材包与界面均不做"真实主体"暗示。
- **文案事实边界（decisions #29）**：只使用素材包与 DB 事实；不虚构人物姓名/身份/亲历、素材外年份/年限/距离、配送时效/库存承诺、活动与认证名次；引用认证/名次须保留素材原文的主语与范围；农户口述只作无人称语感，文化母题只作意象借用。
- **版本管理**：素材改 JSON 即生效，答辩前可直接调；不进 DB、不做后台编辑（现场自定义留 M7）。

## 2. Agent 2 · 包装设计智能体（文创视觉生成）

| 项 | 内容 |
| --- | --- |
| 职责 | 根据 Agent 1 的故事，生成 IP 形象与包装视觉 |
| 输入 | Agent 1 的品牌故事 + IP 定位语 |
| 处理 | 调用图像生成 API → 生成 IP 形象插画 / 包装图案 |
| 输出 | 图片资产（IP 形象、包装设计图） |
| 依赖 | SiliconFlow 文生图网关（OpenAI 兼容，decisions #13，细项见 2.1） |
| 优先级 | 冲刺阶段（接口已定 decisions #13，启动前实测模型与定价） |

### 2.1 图像生成接入细项（decisions #13）

- **网关**：SiliconFlow `POST https://api.siliconflow.cn/v1/images/generations`
- **调用与鉴权**：Bearer API Key；OpenAI SDK 兼容（换 `base_url` 即可），与文字端点（#2）共用同一套 OpenAI 兼容封装思路（`agents/llm.py`）
- **候选模型**：`Kwai-Kolors/Kolors`、`Qwen/Qwen-Image`（Agent 2 启动前实测中文字形与画风后 pin 型号）
- **常用参数**：`prompt` / `image_size`（如 `1024x1024`）/ `negative_prompt` / `num_inference_steps` / `seed`（固定 seed 可复现同一张图）
- **实现要求**：
  - 返回的图片 URL 仅 1 小时有效 → 生成后立即下载转存本地，`agent_artifact` 只存本地路径
  - 请求头 `X-Enable-Watermark: 0`，不保留「AI 生成」默认水印
  - 定价与限流平台文档未列明，注册后在后台确认

## 4. Agent 4 · 算账溯源官（溢价核算 + 一物一码）

两项工作：

### 4.1 溢价核算（纯计算为主）
对比散装均价 vs 文创礼盒定价，计算溢价率，输出定价建议。
**不需要 LLM 也能跑**（LLM 只负责把结论说成人话）。

### 4.2 扫码溯源 H5（ `/t/:code`）
顾客扫礼盒二维码 → 手机打开溯源页：

- **时间线**：该礼盒从采摘 → 集货仓 → 冷链车 → 前置仓 → 签收的全程记录
  （读 `trace_event` 流水表，`trace_code` 只锚 `pallet_id`，见 decisions #15）
- **IP 口吻文案**：以 IP 角色第一人称讲述这段旅程（复用 Agent 1 已定稿的品牌故事，答辩前预生成落库，见 decisions #11）

> 💡 这是 Agent 与沙盘联动的最直观证明：沙盘里记录的每一次运输，就是溯源故事。

| 优先级 | ⭐ MVP（时间线版，decisions #16）：闭环收口件，非答辩高光，最小打磨 |

## 5. Agent 5 · 调度指挥官（孪生调度，护城河）

| 项 | 内容 |
| --- | --- |
| 职责 | 监控各仓库存，给出调货建议 |
| 输入 | 实时库存水位（模拟引擎推送） |
| 处理 | 规则引擎触发（如"某仓 < 阈值 且 源仓充足"）→ 计算调拨量 → LLM 把建议说成人话 |
| 输出 | 调度建议（在 3D 地图上画出路线 + 文字说明） |
| 依赖 | 模拟引擎的数据 + LLM（仅润色话术） |
| 优先级 | 展示位：**可伪**（规则触发 + 生成话术），不必真做优化求解 |

## 6. 人机协同（答辩卖点）

- Agent 产出物统一进入 `agent_artifact` 表，状态流转：`AI 初稿 → 人工润色 → 定稿`
- 前端 Agent 工作台提供审阅/编辑界面，演示"AI 80% + 人工 20%"的润色闭环

## 7. LLM 接入规范

- 统一走 `agents/llm.py` 封装的 OpenAI 兼容客户端
- 配置项：`OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL`（文本模型 `deepseek-ai/DeepSeek-V3.1-Terminus`，decisions #23；直出正文、支持流式，封装仍应忽略可能出现的 `reasoning_content`）
- 所有 Agent 的 Prompt 集中管理（便于答辩时展示与调优）
- 演示数据策略（已定，decisions #11）：答辩前预生成入库为主，现场全命中数据库；保留一个"实时生成"演示位作加分项
